# Спецификация формы подрядчика

## Назначение

Форма предназначена для создания и просмотра отчёта о выполненной работе по заявке. Основной пользователь — подрядчик, который заполняет отчёт и сразу завершает заявку одним действием. Директор и администратор могут создавать отчёты без автоматического завершения заявки.

**URL:** `/works/new` (с обязательным `?request_id={id}` для подрядчика)

**Доступ:** `contractor`, `director`, `admin`

---

## Рабочий процесс подрядчика

1. После входа в систему подрядчик попадает на страницу **Заявки** (`/requests`).
2. Страница содержит три вкладки:
   - **Новые** — заявки, которые ещё никто не взял в работу;
   - **В работе** — заявки, назначенные на текущего подрядчика (включая взятые им самостоятельно или назначенные директором/администратором);
   - **Завершённые** — заявки со статусом `completed`.
3. Подрядчик может:
   - нажать **«Взять в работу»** на новой заявке — заявка переходит в статус `in_progress` и назначается на него;
   - открыть назначенную заявку и нажать **«Создать отчёт»** — открывается форма `/works/new?request_id={id}`.
4. В форме подрядчик заполняет отчёт и нажимает **«Завершить»**. Система:
   - создаёт запись о работе (`POST /works`);
   - загружает фотографии (`POST /works/{id}/photos`);
   - завершает заявку (`PUT /requests/{id}/complete`).
5. После успешного сохранения подрядчик возвращается на страницу `/requests`.

> **Важно:** подрядчик может создать отчёт только по заявке, назначенной на него. Кнопка «Создать отчёт» не отображается:
> - на новых заявках (пока заявка не взята в работу);
> - на заявках, назначенных другому исполнителю;
> - на завершённых заявках.

> **Важно:** если отчёт для заявки уже существует, подрядчик не может его редактировать — редактирование доступно только администратору. При попытке открыть форму для такой заявки кнопка «Завершить» блокируется и выводится сообщение об ошибке.

## Поля формы

### 1. Дата работы (`work_date`)

- **Тип:** Date picker
- **Обязательное:** Да
- **Формат:** YYYY-MM-DD (отображается как DD.MM.YYYY)
- **Валидация:** Не может быть в будущем

### 2. Корпус (`building_id`)

- **Тип:** Выпадающий список (select)
- **Обязательное:** Да
- **Источник:** Справочник `buildings`
- **Особенность:** при открытии формы из заявки корпус подтягивается автоматически из заявки

### 3. Услуги (`services`)

- **Тип:** Множественный autocomplete (react-select AsyncSelect)
- **Обязательное:** Да (минимум одна услуга)
- **Источник:** Справочник `services`
- **Поиск:** По подстроке в названии
- **При выборе:** подтягиваются `unit` и цена из справочника
- **Количество:** > 0
- **Валидация:** услуги не должны дублироваться

### 4. Описание работы (`description`)

- **Тип:** Текстовая область (textarea)
- **Обязательное:** Да
- **Валидация:** Минимум 5 символов
- **Placeholder:** "Подробное описание выполненных работ…"

### 5. Материалы (`materials`)

- **Тип:** Множественный выбор с поиском
- **Обязательное:** Нет
- **Источник:** Справочник `materials`
- **Валидация:** количество > 0, материалы не должны дублироваться

### 6. Фотографии (`photos`)

- **Тип:** Drag & Drop зона + кнопка выбора
- **Обязательное:** Да для подрядчика; опционально для директора/администратора
- **Максимум:** 20 фото на одну работу
- **Форматы:** JPG, JPEG, PNG
- **Максимальный размер оригинала:** 10 МБ на файл
- **Сжатие:** Автоматическое на сервере до 1 МБ, размер до 1920 px по длинной стороне

## Пользовательский сценарий

### Сценарий 1: Подрядчик создаёт отчёт и завершает заявку

1. Подрядчик заходит на `/requests`.
2. Переходит на вкладку «Новые».
3. Находит заявку и нажимает **«Взять в работу»**.
4. Заявка перемещается во вкладку «В работе».
5. Подрядчик нажимает **«Создать отчёт»**.
6. Открывается форма `/works/new?request_id={id}` с предзаполненным корпусом, услугой и описанием из заявки.
7. Подрядчик уточняет дату, количество, добавляет материалы и загружает фото.
8. Нажимает **«Завершить»**.
9. Система создаёт работу, загружает фото и переводит заявку в статус `completed`.
10. Подрядчик возвращается на `/requests`.

### Сценарий 2: Попытка повторного редактирования

1. Подрядчик открывает заявку, для которой уже создан отчёт.
2. Нажимает «Создать отчёт» (или открывает `/works/new?request_id={id}`).
3. Система загружает существующий отчёт в форму только для просмотра.
4. Кнопка «Завершить» заблокирована.
5. Выводится сообщение: «Редактирование отчёта доступно только администратору».

### Сценарий 3: Директор создаёт отчёт без завершения

1. Директор открывает заявку и нажимает **«Создать отчёт»**.
2. Заполняет форму.
3. Нажимает **«Сохранить запись»**.
4. Работа сохраняется, заявка остаётся в статусе `in_progress`.

## Валидация на фронтенде

| Поле | Правило | Сообщение об ошибке |
|------|---------|---------------------|
| Дата работы | Обязательно, не в будущем | «Дата работы не может быть в будущем» |
| Корпус | Обязательно | «Выберите корпус» |
| Услуги | Минимум одна, количество > 0 | «Выберите хотя бы одну услугу» / «Количество услуги … должно быть больше 0» |
| Описание | Минимум 5 символов | «Описание должно быть не менее 5 символов» |
| Фото (подрядчик) | Минимум 1, максимум 20 | «Загрузите хотя бы одну фотографию» / «Максимум 20 фотографий» |
| Материалы | Количество > 0, без дублей | «Укажите количество» / «Материалы не должны дублироваться» |

## Валидация на бэкенде

- Проверка существования корпуса, услуг, материалов.
- Проверка активности услуг и материалов.
- Контроль дублирования отчёта для одной заявки (`POST /works` возвращает 400, если отчёт уже существует).
- Проверка прав: подрядчик может создавать отчёт только по заявке, назначенной на него.
- `PUT /requests/{id}/complete` требует наличия описания и хотя бы одной услуги в отчёте (фото и материалы не обязательны для завершения через этот endpoint).

## Права доступа

| Действие | contractor | director | admin |
|----------|------------|----------|-------|
| Просмотр `/requests` | Свои заявки + новые | Все | Все |
| Взять заявку в работу | Да | Да | Да |
| Создать отчёт | Только по назначенной заявке | Любая незавершённая | Любая незавершённая |
| Кнопка в форме | «Завершить» (сохраняет + завершает) | «Сохранить запись» | «Сохранить запись» |
| Редактировать существующий отчёт | Нет | Нет | Да |
| Завершить заявку | Только свою назначенную | Любую в работе | Любую в работе |

## UX / UI требования

1. **Навигация:** у подрядчика в меню только пункт «Заявки»; пункт «Новая работа» отсутствует.
2. **Вкладки на `/requests`:** Новые / В работе / Завершённые.
3. **Предзаполнение:** при открытии формы из заявки подтягиваются корпус, услуга и описание.
4. **Блокировка повторного сохранения:** если отчёт уже существует, кнопка отправки формы недоступна подрядчику.
5. **Подтверждение при уходе:** если форма заполнена и не сохранена, показывать стандартное предупреждение браузера.
6. **Автосохранение черновика:** данные формы сохраняются в `localStorage` каждые 30 секунд (для незавершённых форм).
7. **Hot keys:** `Ctrl+Enter` — отправить форму.
