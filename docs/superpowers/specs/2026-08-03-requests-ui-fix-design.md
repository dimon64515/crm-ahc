## Резюме

Рефакторинг UI модуля заявок для исправления багов (двоение заявок, невозможность завершения) и улучшения UX для подрядчиков.

## Проблемы

1. **Двоение заявок при сохранении** — нет защиты от двойного нажатия кнопки
2. **Не дает завершить заявки** — непонятный flow, нет ясного UX
3. **Меню "⋯"** — лишний уровень вложенности, кнопки должны быть в карточке
4. **Главная страница подрядчика** — нет удобного списка заявок с вкладками

## Требования

### Для подрядчика (contractor)

- Главная страница — список заявок с вкладками: Новые / В работе / Завершённые
- Кнопку "Новая работа" убрать с дашборда
- Flow завершения: Взять в работу → Карточка → Создать отчет → Форма → Завершить

### Для всех ролей

- Убрать меню "⋯", все кнопки в карточке заявки
- Защита от двойного нажатия на всех кнопках действий
- Понятные сообщения об ошибках

## Flow завершения заявки

### Последовательность для подрядчика

1. **Новая заявка** → кнопка **"Взять в работу"**
   - Действие: `PUT /requests/{id}/take`
   - После успеха: переход в карточку той же заявки

2. **В работе, нет отчёта** → кнопка **"Создать отчет"**
   - Действие: переход на `/works/new?request_id={id}`
   - После создания работы: возврат в карточку

3. **В работе, есть отчёт** → кнопка **"Завершить"**
   - Действие: `PUT /requests/{id}/complete`
   - Проверки на бэкенде: описание + фото + материалы есть
   - После успеха: переход в список "Завершённые"

### Защита от двойного нажатия

На всех кнопках действий:

```javascript
const [actionLoading, setActionLoading] = useState(false);

const handleAction = async (apiCall, id) => {
  if (actionLoading) return; // Ранняя блокировка
  setActionLoading(true);
  try {
    await apiCall(id);
    // обновление данных
  } finally {
    setActionLoading(false);
  }
};
```

## Обработка ошибок

### Исправление двойного сохранения

В `RequestNewPage.jsx`:

```javascript
const [submitting, setSubmitting] = useState(false);

const handleSubmit = async (e) => {
  e.preventDefault();
  if (submitting) return; // Ранняя блокировка
  setSubmitting(true);
  // ... дальнейший код
};
```

### Сообщения об ошибках

| Ситуация | Сообщение |
|----------|-----------|
| Нет отчёта при завершении | "Сначала заполните отчет по работе" |
| Нет фото | "Прикрепите хотя бы одно фото работы" |
| Нет материалов/услуг | "Добавьте материалы и услуги в отчет" |
| Успешное действие | Тост "Действие выполнено" |

## API

Используются существующие эндпоинты без изменений:

- `PUT /requests/{id}/take` — взять в работу
- `PUT /requests/{id}/complete` — завершить
- `GET /requests?status=...` — фильтрация по статусу

Дополнительная фильтрация на фронтенде:
- "В работе" для contractor по `executor.id === user.id`
