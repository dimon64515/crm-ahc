# Spec: Рефакторинг AGENTS.md

## Цель
Устранить warning о превышении 32 KB в `AGENTS.md`, разбив разросшийся файл на систему тематических инструкций без потери полезной информации для AI-агентов.

## Текущее состояние
- `AGENTS.md`: 32 717 байт, 386 строк.
- Warning: файл превышает рекомендуемый лимит 32 KB.
- Есть дублирование: пункт про soft delete повторяется дважды (под номерами 4 и 5).
- Часть информации дублирует `docs/`.

## Итоговая структура

### `AGENTS.md` — главный роутер (~5–8 KB)
Содержит только суть, необходимую при каждом обращении к проекту:
- Обзор проекта
- Ролевая модель (краткая таблица)
- Минимальная структура проекта (только ключевые пути)
- Общие правила стиля (язык, базовые соглашения)
- Роутер: куда обращаться за деталями (`AGENTS_BACKEND.md`, `AGENTS_FRONTEND.md`, `AGENTS_DEPLOY.md`)
- Полезные ссылки

### `AGENTS_BACKEND.md` — backend-инструкции
- Технологический стек (backend-часть и зависимости)
- Архитектура backend (модели, схемы, роутеры, сервисы)
- Основные бизнес-правила, относящиеся к backend (soft delete, историчность цен, импорт, отчёты, бэкапы)
- Безопасность (JWT, роли, CORS)

### `AGENTS_FRONTEND.md` — frontend-инструкции
- Маршруты frontend
- Архитектура frontend (стили, состояние, API, формы)
- Стиль кода React/JS
- Примечание про `date-fns`, если актуально

### `AGENTS_DEPLOY.md` — deploy и инфраструктура
- Сборка, запуск и команды
- Docker Compose
- Деплой
- Тестирование

## План реализации
1. Создать `AGENTS_BACKEND.md` и перенести туда backend-разделы.
2. Создать `AGENTS_FRONTEND.md` и перенести туда frontend-разделы.
3. Создать `AGENTS_DEPLOY.md` и перенести туда deploy-разделы.
4. Переписать `AGENTS.md` в сокращённый роутер.
5. Удалить дублирование пункта про soft delete.
6. Проверить, что все ссылки между файлами корректны.

## Критерии успеха
- `AGENTS.md` меньше 32 KB (цель — до 10 KB).
- Warning о превышении лимита не появляется.
- Вся информация из старого `AGENTS.md` сохранена в одном из новых файлов.
- Дублирование soft delete устранено.
